# Matched width bound and ECommerce reconciliation

Run `python check_widths.py PATH_TO_EXTRACTED_OR2`. Recomputes both November blocks' full-projection interval widths and two nodewise upper bounds from nine saved release streams. At issue t, the main-text H sums the anchor's squared errors over all earlier dates, including not-yet-reported ones. It is available after the test for this diagnostic. The second bound sums only errors on reports eligible at issue t; nonnegative outstanding reservations make this a valid, tighter bound under delayed settlement. Medians pool exactly the same node, issue and run positions as the archived width summaries. The bounds are caps, not predictions of realized width.

Run `python ecommerce.py` to reproduce the two ECommerce summaries from the 27 stream records. To regenerate the inputs from the original stored forecasts, run `python ecommerce.py --streams PATH_TO_UNIFIED_STREAMS`. The generator verifies forecast and context checksums, checks rank, compares raw PIR, coherent PIR and the full release, and recomputes exact pre-release feasibility under the full path’s own allowance. The issue proportion counts issues with at least one candidate coordinate outside its allowance; it differs from the node-sequence breach percentage obtained by releasing the unprotected target. Window pooling counts 18 zero-credit 72-step windows; the continuous protocol counts nine uninterrupted 144-step episodes on the same dates.
