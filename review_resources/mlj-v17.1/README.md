# CPOR · Machine Learning minor revision 17.1 · 15 November 2026

In the extracted OR2 directory, install the root Python 3.11 requirements in a clean environment. Run the following from that directory.

|Paper result|Command and expected output|
|---|---|
|Main Table 6, S32 original-unit/percentage comparisons, S35| `python v17_1/check_tables.py`. Rebuilds the seven-dataset contrasts from node/run records and the four November action/history cells from per-run records. The S35 differences round to 0.195, 1.678 and 1.873 MW. S32 fixed-group SDs are the previously reported, matched v17 Table 7 breakdown.|
|Table S32 statistical tests, Table S33 publication, S9 certificates| `python v17/check.py`. Recomputes the dataset effects and exact sign-flip tests, regenerates both November rules including separate delayed allowances, audits stored nodewise envelopes and prefixes, and verifies all 189 fixed-class certificates. Expected counts are 94/126 and 45/63 strict separations, and 5,184 node/date checks per November arm.|
|One model-to-release example contributing to Table S33|With CUDA PyTorch (tested with 2.11.0+cu128), run `python v17_1/model_to_release.py`. It loads TorchScript exports of the frozen AEMO DLinear run 1 model and its PIR adapter, rebuilds all 24-observation delayed contexts using the first-report timestamps, generates the 12-step blocks and PIR adjustments, reconciles them and runs both protected rules. Expected overall RMSEs round to 568.305 and 569.164 MW for Full and Independent. Original checkpoint hashes, export hashes, normalization and the retrieval cutoff are in model_receipt.json. The PIR inference export includes the fixed retrieval index. The example uses the native 24 by 6 context, batch size one and 96 release dates. Its numerical acceptance checks use 0.005 MW absolute plus a relative tolerance of 2e-6; protection of the newly generated paths is checked separately. The historical publication tests run on CPU from the original saved candidates.|

In the public tag use the same commands with `review_resources/mlj-v17/` in place of `v17/` and `review_resources/mlj-v17.1/` in place of `v17_1/`. The CPU requirements are in `review_resources/mlj-v17/temporal/kernel/requirements-aemo.txt`. The full historical OR2 entry is `python check_results.py`. The separately identified PyTorch inference test requires a compatible CUDA device and PyTorch installation.

training_coverage.csv has one row for each of the 63 benchmark combinations. It gives stage-specific model identities, PIR receipt identities and input anchors for the three protocols. Paths in the provenance columns refer to the original research archive. Of 375 fit-stage entries, 331 had a matched weight file at inventory, 12 carry a receipt digest, and 32 lack a checkpoint identity. The 55 complete-identity combinations therefore do not imply 55 downloadable collections of all model weights. Most distributed tests start from saved inputs. The two executable model artifacts here cover the DLinear November example. This release adds no new forecast period or performance comparison.
