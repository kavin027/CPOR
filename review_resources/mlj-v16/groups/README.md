# Flexible protected PIR release controls

The November 15 protocol was written before scoring these rules. Its SHA-256 is 41f9177e163b9cba91d2c15e15cc6c90489439e81161282ee46087a8bd150404. These are retrospective tests on known streams. There are 7 datasets, 3 backbones and 3 training runs, each with two windows and one continuous trajectory. The primary comparison is Full versus Independent on the 144-issue continuous protocol, using mean-node RMSE in original units. All rules receive the archived coherent PIR candidate and representations, NNLS reference and representations, inverse pre-calibration variances, allowance and immediate feedback.

**Read or check the results.** With Python 3.11, numpy 1.25.2 and pandas 2.2.3, run `python analyze.py --check` here. The script recalculates all summary tables from records/node_rmse.csv.gz, arithmetic_audit.csv and the two timing logs. node_rmse contains every method on each named node and trajectory, including the reference and unprotected coherent candidate. The five AEMO regions and system use the archived order. The scopes for other datasets come from the original node map. Ratios to the reference are omitted when its RMSE is exactly zero. Exact ties are retained. Times for prior methods are not imputed.

**New release rules.** For group G form the column sum of the supplied aggregation columns multiplied by the corresponding latent candidate-minus-reference corrections. Close the last direction on the stored target minus the stored anchor. At each issue minimize weighted squared distance to the target over a coefficient per group in [0,1], with every observed node inside its protection interval. Independent assigns each underlying component its own coefficient. It permits any coordinatewise interpolation between the two recorded underlying representations. Full can leave this coordinatewise box and can change the direction of a correction. The fixed 4- and 8-group rules split the archived bipartition into ascending-index halves recursively. The adaptive rules rank each component by the fraction its own correction can afford in isolation at the current node intervals (capped at 1, minimum across affected nodes, ascending component index breaks ties), then take near-equal consecutive blocks. The order uses the reference, candidate and this arm's past released errors. The six arms never share balances. A numerical guard may adjust a stored node by a rounding residual; this numerical release tolerance is distinct from the exact affine class assessed by the earlier hindsight certificates.

**Execution and inputs.** The v15 inputs.csv manifest lists the paths and SHA-256 hashes of the four archived caches per trajectory. The original context contains the aggregation matrix, pre-calibration variances, bottom representations, node anchors and the labels. PIRCoherent contains the reconciled candidate and its bottom representation, and PIRFull and PIRTwoGroup pin the reused outputs. The previously published compact v15 fixed-two path inputs alone do not specify the directions for all latent components. For algorithm replay use the original caches from the author, identified by these hashes. From this directory run:

    python run_groups.py --index PATH/TO/v15/inputs.csv --archive PATH/TO/ARCHIVE --out OUTPUT --workers 8
    python audit_outputs.py --index PATH/TO/v15/inputs.csv --archive PATH/TO/ARCHIVE --out OUTPUT --workers 8

ARCHIVE contains streams/ and node_map.csv. Core dependencies for replay are Python 3.11, NumPy 1.25.2, SciPy 1.16.3 and Clarabel 0.11.1. Workers use one BLAS thread each in the original study. The drivers verify the four input hashes before computing. Exact dyadic prefix and envelope checks in audit_outputs.py use integer arithmetic and an algebraically independent formula for the scalar supremum. The audit was run against each stored publication. Run-level solver events in arithmetic_audit.csv apply only to the six new methods. For reused methods only the independently computed node dates, envelope events, prefix events and ever-violating sequences in that file are measured.

**Aggregation and timing.** Confidence statements should treat the seven datasets as the empirical units. Windows, runs and nodes share labels. Equal-dataset improvements first average window RMSE within the matched dataset, backbone and run before forming relative reductions. Summary/node_reference.csv first averages RMSE within each named node, then counts nodes and computes ratios. Summary/verified_subset.csv removes both windows and continuous trajectories for the eight PatchTST dataset/run combinations with incomplete late-stage checkpoint provenance. It first averages retained runs inside each dataset–backbone cell, then gives each backbone and each dataset equal weight. Its 55 remaining combinations still require the original prediction caches for bit-level replay. publication_ms.csv.gz covers all new controls under 12 workers with one BLAS/solver thread per worker. Its numbers should only be compared across those new controls. matched_time.csv.gz is a separate serial, single-thread replay of DLinear/run 1 for all seven continuous datasets (1,008 releases per rule). Full and Independent alternated order; both used the same AMD Ryzen 9 8945HX host, reference and forecast inputs, pre-initialized numerical paths, and performed the exact envelope check inside the clock. Input file access, ledger settlement after publication and model fitting are outside this clock. Full uses the published v15 release implementation. Platform and implementation costs both enter the observations. All reproduced predictions in the timing replay match the previously scored predictions bit-for-bit.


**Self-contained release replay.** Run `python check_example.py` from this directory. The compact demo is the October AEMO/DLinear/run 1/continuous 144-issue trajectory. It supplies the aggregation matrix, forecasts, representations, variances, aggregate regional observations and expected releases. Each decision only receives its current candidate, reference and actual allowance. A separate label delivery updates the allowance after release. The independent audit then checks all 864 node–issue pairs per rule. Binary equality was observed for all six rules with the pinned toolchain. A different numerical stack must meet the existing release reproduction tolerance and all exact envelope and prefix tests.
